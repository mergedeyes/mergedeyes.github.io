Mainframe

A terminal control room for your projects:
browse, edit, build, run, test, install, deploy and commit, one key each.

Getting started · Documentation · Keys · Issues

Mainframe is a file browser for the terminal that knows what your projects are. Open a Rust, Go, Node, Python, Zig, CMake, Meson, Make, just, .NET or Visual C++ project, and b builds it, t tests it, r runs it. Errors are one key away from your editor, every project keeps its own output, and your work goes to your PATH, a Raspberry Pi or a GitHub release without leaving the window.

Everything it runs shows up in an output pane with the exact command first. Nothing happens behind your back, and nothing is written into your projects unless you ask for it.

Why Mainframe

  • One key per job, in every project. The same keys build, test and run a Cargo crate, an npm app or a Python package. T lists everything else a project can run: scripts, make targets, binaries, examples.
  • Output that stays with its project. Each project keeps its own output tabs. Move on to another one and its builds keep running; come back and everything is where you left it, even after a restart. A long task notifies you when it's done.
  • From error to fix in two keys. n jumps to the next file:line in the output, Enter opens your editor right there. Watch mode reruns the tests whenever you save.
  • Ship it without switching tools. i installs a build on your PATH and updates its desktop entry; p in it pulls first, so what you just merged is what gets installed. D builds, copies it to a Pi or a server over ssh and swaps it in, keeping the old one as a backup. It can build a clean main while you're in the middle of a feature.
  • Releases in one go. g r bumps the version, commits it (or opens a pull request), tags it, pushes and follows the release workflow.
  • Your disk back. C finds debug builds, node_modules, virtualenvs and caches in all your projects and worktrees, with their real size on disk, and clears what you pick.
  • Your projects at a glance. J lists every project, most recently used first, with running tasks and open todos. Notes and todos per project stay outside the repo, so they never end up in a commit.

Features

  • Files: fuzzy file finder, filter, zoxide jumps, marks across folders, copy, move, trash, git status on every entry, preview with diffs.
  • Running: build, release build, test, run single files, task picker, output tabs, watch mode, search and save output, jump to file:line.
  • Git: stage from the list, commit, amend, push another branch, new branches with names tidied for GitHub, branches numbered in merge order with their dates, cleanup of merged branches, worktrees, stash, a GitHub repo for any folder, releases with CI.
  • Install and deploy: install picker with build info, PATH checks, and pull-then-install for the newest version, desktop entries, deploy targets with backups, rollback and systemd services, set up and edited in the TUI.
  • Projects: project picker, notes and todos, new projects with git init, a CLAUDE.md template for Claude Code that Ctrl-L brings into any existing project.
  • Cleanup: build output, dependencies and caches, across projects and worktrees, measured as on disk on compressed btrfs.
  • Blog: in your Jekyll blog repo, L lists drafts and posts; write them in a built-in Markdown editor with live preview and autosave, then publish, push and get told when GitHub Pages has the post live. n keeps a /now page, with its "updated" date set when you push it.

Getting started

There are no prebuilt releases yet. Build Mainframe with Rust 1.88 or newer:

git clone https://github.com/mergedeyes/Mainframe && cd Mainframe
cargo install --path . --root ~/.local
mainframe ~/Projekte

Press J to pick a project, b to build it and ? for the keys. Installation lists the optional tools and how to land in the last folder when you quit. First steps is a ten-minute tour.
