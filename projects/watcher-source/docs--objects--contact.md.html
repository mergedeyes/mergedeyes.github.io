contact

A contact is someone who receives notifications: by email, webhook, Slack, Microsoft Teams, Telegram, ntfy, Gotify, PagerDuty, Jira or a script of your own, or several of them. A contact alone receives nothing: a notify rule decides which contacts get which notifications.

[contact.oncall]
email = "oncall@example.com"

[[notify]]
contacts = ["oncall"]

The contact oncall gets an email for every problem and recovery.

Email needs an SMTP server in watcher.toml, see Notifications.

Fields

Field Default Description
email One address, or a list of addresses.
webhook An http:// or https:// URL. Watcher sends each notification as JSON in a POST request; see Webhook.
slack A Slack incoming webhook URL. See Slack.
teams A Microsoft Teams webhook URL, from the Workflows template "Post to a channel when a webhook request is received". See Microsoft Teams.
telegram.token Telegram: the bot's token from BotFather. See Telegram.
telegram.chat Telegram: the chat ID (a number, -100… for groups) or @channelname.
ntfy An ntfy topic URL, https://ntfy.sh/my-topic. Or a table { url, token } for a topic that needs an access token. See ntfy.
gotify.url Gotify: the server's URL. See Gotify.
gotify.token Gotify: an application token.
pagerduty A PagerDuty Events API v2 routing key (integration key). Problems open incidents, recoveries resolve them. See PagerDuty.
jira.url The Jira site, https://acme.atlassian.net or an on-premise server. Problems become issues, one per open problem; repeats and escalations add comments; the recovery comments and can close the issue. See Jira.
jira.project The key of the project issues are created in, for example OPS.
jira.email Jira Cloud: the account the API token belongs to. Leave out for Data Center/Server.
jira.token Jira Cloud: an API token. Data Center/Server: a personal access token.
jira.cloud detected true for Jira Cloud (REST v3), false for Data Center/Server (REST v2). Detected from *.atlassian.net in the URL.
jira.issue_type Task The issue type new issues get. It must exist in the project.
jira.close A transition (by its name, or the status it leads to, for example Done) run when the problem recovers. Without it, recoveries only comment.
script A program to run for each notification, with arguments, for example /usr/local/bin/send-sms --to ops. It gets the notification as JSON on stdin. See Scripts.
groups Contact groups the contact belongs to. See contactgroup.

A contact without any of email, webhook and the other channels gives a warning.

Examples

One email address

[contact.alice]
email = "alice@example.com"

Several addresses

[contact.alice]
email = ["alice@example.com", "alice@pager.example.com"]

A chat webhook

[contact.chatops]
webhook = "https://hooks.example.com/watcher"

Email and webhook

The contact gets each notification on both channels.

[contact.noc]
email = "noc@example.com"
webhook = "https://chat.example.com/hooks/watcher"

Slack and Microsoft Teams

[contact.team-chat]
slack = "https://hooks.slack.com/services/T0000/B0000/XXXXXXXX"
teams = "https://prod-00.westeurope.logic.azure.com/workflows/…"

Telegram

[contact.oncall-phone]
telegram = { token = "123456789:AAH…", chat = -1001234567890 }

Push to a phone with ntfy or Gotify

[contact.alice]
ntfy = "https://ntfy.sh/acme-ops-7f3k2"

[contact.bob]
ntfy = { url = "https://ntfy.example.com/ops", token = "tk_…" }
gotify = { url = "https://gotify.example.com", token = "AbCdEf…" }

PagerDuty

[contact.pagerduty]
pagerduty = "R0123456789ABCDEF0123456789ABCD"

Jira

[contact.helpdesk]
jira = { url = "https://acme.atlassian.net", project = "OPS", email = "watcher-bot@acme.com", token = "ATATT…", close = "Done" }

On a self-hosted Jira (Data Center/Server), with a personal access token and no email:

[contact.helpdesk]
jira = { url = "https://jira.acme.com", project = "OPS", token = "NjE2…", issue_type = "Incident" }

A script

[contact.sms]
script = "/usr/local/bin/send-sms --to +491701234567"

In a contact group

[contact.alice]
email = "alice@example.com"
groups = ["dba"]

Testing

watcher notify test oncall

This sends a test message to the contact on all its channels.

To see which notifications a contact gets:

watcher config explain contact oncall
