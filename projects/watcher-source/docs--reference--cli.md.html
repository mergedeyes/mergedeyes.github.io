Command line

watcher <command> [options]

Commands that take a PATH accept either a watcher.toml, or a directory of object files (then there is no watcher.toml). Without a PATH, Watcher uses ./watcher.toml, then /etc/watcher/watcher.toml.

The log level is set with RUST_LOG, for example RUST_LOG=debug watcher run.

run

Runs all checks and serves the web UI and the API.

watcher run [PATH] [options]
Option Default Description
--all Log every result, not only state changes.
--max-concurrent N 64 How many checks may run at the same time.
--database URL [database] in watcher.toml Database to use. Also: environment variable WATCHER_DATABASE_URL.
--no-database Run without a database; results are not stored.
--no-auth No login. Only listens on loopback.
--listen ADDR listen in watcher.toml Address to listen on, for example 0.0.0.0:8080.

If PATH points to a watcher.toml that doesn't exist yet, the setup wizard starts in the browser. SIGHUP reloads the object files.

watcher run /etc/watcher/watcher.toml
watcher run examples/demo/watcher.toml --database postgres://watcher:watcher@localhost/demo

run-check

Runs one command and shows how Watcher reads the result. Needs no configuration. The exit code is the final state: 0 OK, 1 WARNING, 2 CRITICAL, 3 UNKNOWN.

watcher run-check [options] [--] COMMAND...
Option Default Description
--format F auto Output format: auto, nagios, key_value or json.
--timeout D 60s Kill the command after this time.
--shell Run the command with /bin/sh -c.
--warn METRIC=THRESHOLD WARNING threshold for a metric. Can be given several times.
--crit METRIC=THRESHOLD CRITICAL threshold for a metric. Can be given several times.
--output-limit BYTES 65536 Maximum output read per stream (stdout, stderr).
--json Print the result as JSON.

Options go before the command. A single argument is split into words like a shell would; several arguments are used as they are. Commands without a path are found in the default check directories.

watcher run-check -- check_disk -w 20% -c 10% -p /
watcher run-check --shell 'echo "users=$(who | wc -l)"'
watcher run-check --crit 'time=> 2s' -- check_http -H example.com

See Testing a command.

init

Asks questions in the terminal and writes watcher.toml and conf.d/.

watcher init [DIR] [--answers FILE] [--force]
Option Default Description
DIR . Directory to write to.
--answers FILE Take the answers from a file instead of asking. Format: examples/init-answers.toml.
--force Overwrite existing files.

Answers can also be piped to stdin.

With a database, init creates an admin account and offers two-factor authentication for it: it prints a QR code and the key for an authenticator app, asks for a code from the app, and prints the ten recovery codes at the end. In an answers file, totp_secret under [admin] turns it on with a key you already have (base32).

setup

Runs the setup wizard in the browser, then starts Watcher.

watcher setup [DIR] [--listen ADDR]
Option Default Description
DIR . Directory to write to.
--listen ADDR 127.0.0.1:8080 Use 0.0.0.0:8080 to set up a remote machine.

The setup token you need to enter on the page is printed to the log.

config check

Checks the configuration and prints a summary, or every service with its command. Host checks are counted apart and marked (host check).

watcher config check [PATH] [--services]

OK: 4 files, 2 hosts, 4 checks, 5 services, 4 on hosts, 1 host check, 1 contact

  localhost/disk_root  every 30s    check_disk -w '20%' -c '10%' -p /
  localhost/backup     fresh 1day 2h  (passive)

Errors are shown with file and line, and the exit code is 1:

hosts.toml:4: error: host "h1": unknown hostgroup "b"

config explain

Shows the Config Tree: where an object and each of its values come from, and where the object is used.

watcher config explain <host>[/<service>] [-c PATH]
watcher config explain <kind> <name> [-c PATH]

Kinds: host, service, check, hostgroup, servicegroup, contact, contactgroup, downtimegroup, timeperiod, notify, dependency. service <name> explains a service definition and the hosts that have it; <host>/<service> explains the service on one host.

watcher config explain web01
watcher config explain web01/http
watcher config explain service disk
watcher config explain hostgroup linux
watcher config explain notify dba-critical

See Finding out where a value comes from.

config edit

Opens an object file in your editor, locked against changes in the web UI while the editor is open. Afterwards it checks the configuration.

watcher config edit <FILE> [-c PATH] [--force]
Option Description
FILE The file, relative to the config directory (hosts.toml, ui/hosts.toml) or as a path to it (conf.d/hosts.toml). A file that doesn't exist yet is created when you save.
-c PATH watcher.toml, or a directory of object files. Default: ./watcher.toml, then /etc/watcher/watcher.toml.
--force Open it even if someone else is editing it.

The editor is $VISUAL, else $EDITOR, else vi. While it is open, a lock file .hosts.toml.watcher-lock sits next to the file.

$ watcher config edit hosts.toml
anna is editing hosts.toml in the web UI since 10:42
error: not opened; --force edits it anyway

The exit code is 1 if the file is locked, the editor fails, or the configuration has errors afterwards. See Editing at the same time.

notify test

Sends a test message to a contact, on all its channels.

watcher notify test <contact> [PATH]

user

Manages web UI accounts. Accounts are stored in the database.

watcher user add <name> [--admin] [--password-stdin]
watcher user passwd <name> [--password-stdin]
watcher user list
watcher user remove <name>
watcher user totp-off <name>
  • --admin: the user may edit the configuration.
  • Passwords need at least 10 characters. They are asked twice, or read from the first line of stdin with --password-stdin.
  • passwd logs the user out everywhere. remove also deletes the user's sessions and API tokens.
  • list shows totp for users with two-factor authentication.
  • totp-off turns two-factor authentication off, for a user who lost their phone and their recovery codes. The password alone logs them in until they set it up again under Account.

token

Manages API tokens. A token is shown only once, when it is created.

watcher token create <user> <name>
watcher token list <user>
watcher token revoke <user> <name>

watcher token create alice "backup cron job"

db reader

Creates a read-only database login for Grafana, BI tools or SQL, or sets its password. Watcher's database user needs the CREATEROLE right. Run it again after upgrades.

watcher db reader <name> [--password-stdin]

Without --password-stdin, a password is generated and printed. See Read-only login.

secret

Manages keys and passwords for checks over SSH, and API tokens for the Proxmox VE checks. They are stored in the database, encrypted with data_dir/secret.key.

watcher secret new <name> [--replace]
watcher secret import <name> <file> [--passphrase-stdin] [--replace]
watcher secret password <name> [--password-stdin] [--replace]
watcher secret token <name> --id <id> [--secret-stdin] [--replace]
watcher secret show <name>
watcher secret list
watcher secret remove <name>
  • new creates an ed25519 key and prints only the public key to stdout, so you can append it directly: watcher secret new monitor >> authorized_keys.
  • import reads ed25519 or ECDSA keys in OpenSSH, PEM or PuTTY format, and asks for the passphrase if the key is encrypted. RSA is not supported.
  • token stores an API token: --id is its ID (for Proxmox VE user@realm!name, in single quotes because of the !), and the secret is asked for. --secret-stdin reads it from the first line of stdin instead.
  • list shows the fingerprint of keys and the ID of tokens.
  • --replace overwrites an existing secret of the same name.

hostkey

Manages SSH host keys. Watcher stores a host's key on the first connection.

watcher hostkey list
watcher hostkey accept <address>[:<port>]
watcher hostkey forget <address>[:<port>]

See Host keys.

node

Manages nodes. On the hub (role = "hub"):

watcher node add <name>
watcher node token <name>
watcher node list
watcher node remove <name>
  • add adds a node and prints the command that joins it. The join token in it works once, within 24 hours. It also works for a node name that hosts use but that hasn't joined yet.
  • token prints a new join command, also for a node that has joined already, for example after reinstalling its machine. Its current certificate works until it joins again.
  • list shows when each node joined and was last seen, its version and machine, or until when its join token works.
  • remove stops the node's certificate and join token from working. A running hub ends the node's connection within a minute.

On the node's machine:

watcher node join <hub> --token <token> [-c FILE]

join uses the token, keeps the node's key and certificates in data_dir/node/, and sets role = "node" and [node] hub in watcher.toml: the one given with -c, else ./watcher.toml or /etc/watcher/watcher.toml. If none exists, it creates ./watcher.toml. It refuses a watcher.toml with another role. After join, watcher run starts the node.

watcher node join https://hub.example.com:7443 --token wj_… -c /etc/watcher/watcher.toml

Database options

user, token, db, secret, hostkey and node (except node join) need the database. They find it with these options:

Option Description
-c, --config FILE A watcher.toml with [database].
--database URL The database URL. Also: environment variable WATCHER_DATABASE_URL.
