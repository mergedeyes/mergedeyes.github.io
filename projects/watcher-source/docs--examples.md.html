Examples

Complete conf.d/ setups for common cases. Each one passes watcher config check. The plugins come from the monitoring-plugins package; Many websites needs none, it uses built-in checks.

More in the repository: examples/local, examples/demo (needs no plugins), and examples/sinks.toml.

One Linux server

Monitors the machine Watcher runs on: two disks, load, swap and processes. The disk service uses for_each, so the host gets one disk service per entry in vars.disks: disk_root and disk_var.

# conf.d/checks.toml
[check.disk]
command = "check_disk -w $warn$ -c $crit$ -p $path$"
vars = { warn = "20%", crit = "10%" }

[check.load]
command = "check_load -r -w 2,1.5,1 -c 4,3,2"

[check.swap]
command = "check_swap -w 50% -c 20%"

[check.procs]
command = "check_procs -w 400 -c 600"
# conf.d/services.toml
[service.disk]
for_each = "disks"

[service.load]

[service.swap]

[service.procs]
interval = "5m"
# conf.d/hosts.toml
[[host]]
name = "localhost"
services = ["disk", "load", "swap", "procs"]
graph = "load"
vars.disks.root = { path = "/" }
vars.disks.var = { path = "/var" }
# conf.d/contacts.toml
[contact.admin]
email = "admin@example.com"

[[notify]]
contacts = ["admin"]

Web and database servers

A small company network:

  • Every host gets the service group server (SSH) through the host group all, and ping as its host check, which decides whether it is UP or DOWN.
  • Web servers and databases get their services through host groups that match their names.
  • The service group shop doesn't give anyone services. It only groups the web and database services into a "Webshop" view.
  • The DBAs only get critical database problems; on-call gets everything about production hosts.
# conf.d/checks.toml
[check.ping]
command = "check_ping -H $host.address$ -w $warn$ -c $crit$"
vars = { warn = "100,20%", crit = "500,60%" }

[check.ssh]
command = "check_ssh -H $host.address$"

[check.http]
command = "check_http -H $host.address$ -u $url$"
vars.url = "/"
thresholds.time = { warn = "> 500ms", crit = "> 2s" }

[check.https_cert]
command = "check_http -H $host.address$ -S -C 21,7"

[check.pgsql]
command = "check_pgsql -H $host.address$ -d $db$"
vars.db = "postgres"
# conf.d/services.toml
[service.ping]
[service.ssh]
[service.http]
[service.https_cert]
[service.pgsql]
# conf.d/groups.toml
[servicegroup.server]
title = "Server Basics"
services = ["ssh"]

[servicegroup.shop]
title = "Webshop"
services = ["http", "pgsql"]

[hostgroup.all]
members = ["*"]
servicegroups = ["server"]
host_check = "ping"

[hostgroup.web-servers]
title = "Web Servers"
members = ["web*", "test01"]
services = ["http", "https_cert"]

[hostgroup.databases]
title = "Databases"
members = ["db*"]
services = ["pgsql"]

[hostgroup.prod]
members = ["web01", "web02", "db01"]

web02 checks another URL and db01 another database, by setting the var. test01 has a self-signed certificate, so its certificate check is removed.

# conf.d/hosts.toml
[[host]]
name = "web01"
address = "10.0.1.11"

[[host]]
name = "web02"
address = "10.0.1.12"
vars.url = "/health"

[[host]]
name = "db01"
address = "10.0.2.21"
vars.db = "shop"

[[host]]
name = "test01"
address = "10.0.9.1"
  [host.service.https_cert]
  enabled = false
# conf.d/contacts.toml
[contact.oncall]
email = "oncall@example.com"

[contact.alice]
email = "alice@example.com"
groups = ["dba"]

[contact.bob]
email = "bob@example.com"
groups = ["dba"]

[contactgroup.dba]
title = "DBAs"
# conf.d/notify.toml
[[notify]]
name = "prod"
contacts = ["oncall"]
hosts = { groups = ["prod"] }

[[notify]]
name = "dba"
contact_groups = ["dba"]
services = { checks = ["pgsql"] }
states = ["critical"]

Many websites

Monitors several websites from one host entry. for_each creates one HTTP service and one certificate service per site: websites/http_shop, websites/http_blog, websites/http_api, websites/cert_shop, and so on. The host has no address, so it has no host check and is always UP.

Both services use built-in checks, so no plugins are needed. http gets the full URL from the site's vars; tls connects to the site with address, since the host has no address of its own.

# conf.d/services.toml
[service.http]
for_each = "sites"
groups = ["websites"]
vars = { url = "https://$vhost$$path$", path = "/", warn = "1s", crit = "5s" }

[service.cert]
check = "tls"
for_each = "sites"
interval = "1h"
vars = { address = "$vhost$", warn = "21", crit = "7" }
# conf.d/hosts.toml
[[host]]
name = "websites"
services = ["http", "cert"]
vars.sites.shop = { vhost = "shop.example.com" }
vars.sites.blog = { vhost = "blog.example.com", path = "/feed" }
vars.sites.api = { vhost = "api.example.com", path = "/v1/health" }
# conf.d/groups.toml
[servicegroup.websites]
title = "Websites"

Customers (MSP)

A service provider with several customers. Each customer has a host group that matches their host names. The NOC gets every notification, and open problems again every hour until someone acknowledges them. Critical problems that nobody acknowledged within 2 hours go to the NOC lead. Each customer only gets critical problems of their own hosts.

The host group windows has no members: hosts join it themselves with groups = ["windows"].

# conf.d/checks.toml
[check.ping]
command = "check_ping -H $host.address$ -w 200,20% -c 800,60%"

[check.rdp]
command = "check_tcp -H $host.address$ -p 3389"

[check.smtp]
command = "check_smtp -H $host.address$"
# conf.d/services.toml
[service.ping]
[service.rdp]
[service.smtp]
# conf.d/groups.toml
[hostgroup.all]
members = ["*"]
host_check = "ping"

[hostgroup.windows]
services = ["rdp"]

[hostgroup.mail]
members = ["*mail*"]
services = ["smtp"]

[hostgroup.acme]
title = "ACME Corp"
members = ["acme-*"]

[hostgroup.globex]
title = "Globex"
members = ["globex-*"]

One file per customer keeps the hosts apart:

# conf.d/hosts/acme.toml
[[host]]
name = "acme-dc01"
address = "192.0.2.10"
groups = ["windows"]

[[host]]
name = "acme-mail"
address = "192.0.2.25"
# conf.d/hosts/globex.toml
[[host]]
name = "globex-fs01"
address = "198.51.100.5"
groups = ["windows"]
# conf.d/notify.toml
[contact.noc]
email = "noc@msp.example"
webhook = "https://chat.msp.example/hooks/watcher"

[contact.noc-lead]
email = "noc-lead@msp.example"

[contact.acme-it]
email = "it@acme.example"

[[notify]]
name = "noc"
contacts = ["noc"]
repeat = "1h"

[[notify]]
name = "noc-lead"
contacts = ["noc-lead"]
states = ["critical", "down"]
after = "2h"

[[notify]]
name = "acme"
contacts = ["acme-it"]
hosts = { groups = ["acme"] }
states = ["critical", "down"]
on = ["problem", "recovery"]

Backup jobs (passive)

The backup jobs send their result to Watcher after each run. If no result arrives for 26 hours, the service turns UNKNOWN. The mail server backs up every 6 hours, so it gets a shorter freshness and a threshold on the backup duration.

# conf.d/services.toml
[service.backup]
passive = true
freshness = "26h"
# conf.d/hosts.toml
[hostgroup.backup]
services = ["backup"]

[[host]]
name = "fileserver"
groups = ["backup"]

[[host]]
name = "mailserver"
groups = ["backup"]
  [host.service.backup]
  freshness = "8h"
  thresholds.duration = { warn = "> 2h" }
# conf.d/contacts.toml
[contact.backup-admin]
email = "backup@example.com"

[[notify]]
contacts = ["backup-admin"]
services = { name = "backup" }

At the end of the backup script, with a token from watcher token create backup "backup jobs":

curl -fsS -X POST "https://watcher.example.com/api/v1/services/$(hostname)/backup/result" \
  -H "Authorization: Bearer $(cat /etc/watcher-token)" -H 'content-type: application/json' \
  -d "{\"exit_code\": $rc, \"output\": \"BACKUP rc=$rc | duration=${secs}s size=${bytes}B\"}"

Own scripts

Two scripts in checks/ next to watcher.toml, both executable. One prints key=value metrics, the other JSON. Thresholds in the check decide the state of the first one; the second one sets its state in the JSON.

checks/app_queue:

#!/bin/sh
echo "depth=$(redis-cli -h "$1" llen jobs) workers=$(redis-cli -h "$1" scard workers)"

checks/app_health:

#!/bin/sh
curl -fsS "http://$1:8080/health" | jq '{state: (if .ok then "ok" else "critical" end), message: .status, metrics: {latency: .latency_ms}}'
# conf.d/checks.toml
[check.app_queue]
command = "app_queue $host.address$"
thresholds.depth = { warn = "> 1000", crit = "> 10_000" }
thresholds.workers = { crit = "< 1" }

[check.app_health]
command = "app_health $host.address$"
format = "json"
timeout = "10s"
graphs = false
# conf.d/services.toml
[service.queue]
check = "app_queue"

[service.health]
check = "app_health"
interval = "30s"

[servicegroup.app]
title = "App"
services = ["queue", "health"]
# conf.d/hosts.toml
[[host]]
name = "app01"
address = "10.0.5.1"
servicegroups = ["app"]

Copy to a central database

Every result is also written to a reporting database, every five minutes. While the reporting database is down, results wait in a buffer of up to 4 GB on disk.

# conf.d/sinks.toml
[[sink]]
name = "reporting"
type = "postgres"
url = "postgres://watcher@reporting.example.com/watcher"
password_file = "reporting.pass"
flush = { mode = "interval", interval = "5m" }
buffer = { max_size = "4GB" }

A read-only login on the local database, for Grafana:

watcher db reader grafana
