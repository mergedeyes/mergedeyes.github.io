<span class="c1"># {CITY_CODE}_MAP_DATA.json (see bbox_utils.py) under a "special_demand" list.</span>
<span class="c1">#</span>
<span class="c1"># NOTE: Airports are intentionally NOT auto-detected here. Airports already have</span>
<span class="c1"># a separate, working mechanism (AIRPORT_GEOJSON runway/taxiway detection +</span>
<span class="c1"># custom_hubs.json + open_maps.py) that snaps real, CSV-derived commuter jobs</span>
<span class="c1"># into a terminal-precise mega-hub - that's real workplace-commute data with no</span>
<span class="c1"># invented numbers, and stays untouched. If you want a *separate* passenger-</span>
<span class="c1"># volume special demand point for an airport (a different, researched number,</span>
<span class="c1"># not workplace commuting), you can add a "type": "airport" entry to the JSON</span>
<span class="c1"># by hand.</span>
<span class="c1">#</span>
<span class="c1"># LANDMARK TYPES: university, hospital, stadium, museum, zoo, amusement/water</span>
<span class="c1"># parks, plus school and clinic (with a significance filter - see below) -</span>
<span class="c1"># individually significant places where a real, researched capacity/</span>
<span class="c1"># enrollment/attendance number is a meaningful upgrade over treating the</span>
<span class="c1"># building like an ordinary office/residential building.</span>
<span class="c1">#</span>
<span class="c1"># High-count, low-signal categories (neighborhood sports centres, named</span>
<span class="c1"># parks, small ferry docks, "college"-tagged adult-education/vocational</span>
<span class="c1"># buildings) are NOT tracked here at all. Every one of them is ALSO already</span>
<span class="c1"># flagged is_special=True in generate_demand_qzm_local.py's base OSMHandler</span>
<span class="c1"># and gets a boosted share of real CSV-driven commuter demand there - so</span>
<span class="c1"># adding a second, independent special-demand point for the same building on</span>
<span class="c1"># top of that just double-counted it. At city-wide density (thousands of</span>
<span class="c1"># these) that showed up as huge, inflated points sitting on top of each other</span>
<span class="c1"># in-game, since depot's add_points() only ever merges two points of the</span>
<span class="c1"># *same* special-demand type together, and never with a random nearby one of</span>
<span class="c1"># a different type. The base pipeline already models these fine on its own.</span>
<span class="c1">#</span>
<span class="c1"># school and clinic are numerous too, but unlike park/sports_centre/port,</span>
<span class="c1"># they have a real size split worth capturing: a Gymnasium or a genuine</span>
<span class="c1"># medical center is a meaningfully bigger, more distinct piece of demand than</span>
<span class="c1"># an ordinary building, the same way a real university differs from one of</span>
<span class="c1"># its own sub-unit buildings. See _school_is_significant()/</span>
<span class="c1"># _clinic_is_significant() - only entries that pass get recorded at all, so</span>
<span class="c1"># the flood of small Grundschulen and single-doctor Praxis buildings never</span>
<span class="c1"># becomes a candidate in the first place.</span>
<span class="c1">#</span>
<span class="c1"># Also: no commercial/office/retail/shop tags are matched here at all - those</span>
<span class="c1"># only feed the *base* job generation in generate_demand_qzm_local.py (via its</span>
<span class="c1"># own JOB_TAGS), which never opens a browser tab.</span>
<span class="c1">#</span>
<span class="c1"># ONE MORE WRINKLE: big universities tag each faculty/department building</span>
<span class="c1"># separately in OSM (e.g. "FB Veterinärmedizin", "FB Geschichts- und</span>

<span class="c1"># docks used to inflate "port". Two fixes below: a university-tagged node</span>
<span class="c1"># whose own name doesn't read like a real institution (see</span>
<span class="c1"># _looks_like_real_institution) is skipped entirely rather than recorded, and</span>
<span class="c1"># same-type landmark candidates within CAMPUS_MERGE_RADIUS_DEG of each other</span>
<span class="c1"># get merged into one entry (see _merge_nearby_campuses) instead of becoming</span>
<span class="c1"># N separate special demand points for what's really one campus.</span>
