   Design: dark "instrument panel" — deep slate, amber-gold signal
   accent, filesystem-path section labels. Plain CSS, no build step.

     at two different web fonts (Bricolage Grotesque, Inter); now that
     nothing is loaded over the network, both resolve to the same native

/* Animated gradient ring + full-interior glow, revealed on hover — same
   "spinning conic-gradient ring" idea as a nebula/glow button, recolored
   to the site's own accent (amber) + signal (teal) instead of a generic
   neon palette. Shared by project cards and skill chips (.chips li),
   scaled down for the chips since they're much smaller. Two layers per
   element share one rotating gradient:
     ::before — MASKED down to a crisp ring tracing the outline. Masking
                keeps its visible pixels mostly outside the element's own
                painted area, which matters because negative z-index does
                NOT hide a pseudo-element behind its own element's
                background — that background always paints first
                regardless of z-index (learned this the hard way: an
                earlier unmasked ::after washed the whole card in flat
                color instead of glowing).
     ::after  — the SAME gradient, left unmasked and blurred, filling the
                whole interior at low opacity as a soft tinted glow; the
                blur also softens its edge into a light outward halo.
   `--glow-spin-angle` is what actually animates, driving both layers (on
   both element types) in sync. Everything is paused (not just invisible)
   until hover, and dropped entirely under reduced-motion. */
@property --glow-spin-angle {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}
.card::before, .card::after,
.chips li::before, .chips li::after {
  content: "";
  position: absolute;
  inset: -1px;
  background: conic-gradient(from var(--glow-spin-angle), var(--accent), var(--signal), var(--accent));
  opacity: 0;
  pointer-events: none;
  transition: opacity .4s ease;
  animation: glow-spin 6s linear infinite;
  animation-play-state: paused;
}
.card::before, .chips li::before {
  -webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  -webkit-mask-composite: xor;
          mask-composite: exclude;
  z-index: -1;
}
.card::after, .chips li::after { z-index: -2; }
.card::before      { border-radius: 13px; padding: 1.5px; }
.card::after        { border-radius: 13px; filter: blur(12px); }
.chips li::before   { border-radius: 9px; padding: 1px; }
.chips li::after    { border-radius: 9px; filter: blur(6px); }

.card:hover::before, .chips li:has(a):hover::before { opacity: 1; animation-play-state: running; }
.card:hover::after { opacity: .18; animation-play-state: running; }
.chips li:has(a):hover::after { opacity: .22; animation-play-state: running; }

/* The interior glow tints the card, so the dimmer/muted text needs to
   step up a shade on hover to stay readable against it — description
   and license badge sit closest to the tint (top and bottom-right
   corner), the two spots people mentioned losing. */
.card:hover .card__body { color: var(--text); }
.card:hover .license-badge { color: var(--text-dim); }

@keyframes glow-spin { to { --glow-spin-angle: 360deg; } }
@media (prefers-reduced-motion: reduce) {
  .card::before, .card::after, .chips li::before, .chips li::after { animation: none; }
}
/* Cards with data-href are whole-card links to their /projects page
   (see script.js) — the pointer cursor signals that over the card
   body, while the nested <a> tags (title, Repository, Live/demo)
   already get their own pointer cursor as normal links. */
.card[data-href] { cursor: pointer; }
.card__head { display: flex; align-items: center; gap: 1rem; margin-bottom: .7rem; flex-wrap: wrap; }
/* The rule above is still what the generated project-page headers use
   (.project-page__head, further down) - title and tags as flat flex
   siblings that just wrap together, no right-pinning needed there since
   it's a full detail page, not a compact card. Compact CARDS want
   something fussier: title pinned left, and the tag cluster sharing the
   title's own line as far as it fits, with any extra tags wrapping onto
   their own row(s) directly underneath - still flush right, never their
   own separate line below an otherwise-mostly-empty title row. Flexbox
   can't express "share this line, then wrap below" between two flex
   siblings (the tag group either fits and shares the line, or doesn't
   and moves as a whole unit to a new line - no partial split), so cards
   override .card__head to plain block flow and use a right float for
   .card__tags instead: normal text (the title) wraps around a preceding
   float, at any width, splitting itself only as needed. This ONLY
   applies inside an actual .card - .project-page__head has no .card
   ancestor and no .card__tags wrapper (bare <span class="tag"> siblings
   instead), so it's untouched and keeps the flex rule above. Floats have
   no effect on elements that are themselves flex items, which is exactly
   why .card__head has to stop being display:flex for this to work at
   all - and why .card__tags now has to come BEFORE .card__title in the
   markup (a float only affects the flow of content that follows it). */
.card > .card__head { display: block; }
.card > .card__head::after { content: ""; display: table; clear: both; }
.card__tags {
  display: flex;
  flex-wrap: wrap;
  justify-content: flex-end;
  gap: .5rem;
  float: right;
  max-width: 70%;
  margin-left: .8rem;
}
.card__title { font-size: 1.2rem; }
.card__body { color: var(--text-dim); font-size: .96rem; margin-bottom: 1rem; }
