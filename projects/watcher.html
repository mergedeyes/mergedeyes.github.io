Watcher

Infrastructure monitoring that is as easy to set up as it should be,
and always tells you why it does what it does.

Getting started · Documentation · What works today · Issues


A simulated network: 9,500 hosts and 206,000 services in four datacenters.

Watcher checks your servers, network devices and applications, keeps their metrics, and alerts you when something breaks. It is a single program with a web UI built in: no agents to roll out and no add-ons to assemble. The check plugins you already run with Nagios work as they are.

If you have ever asked "why is this host checked every minute?", "where does this threshold come from?" or "why did nobody get paged?", Watcher was built for you. Every setting can be traced to the file and line that set it, and every alert to the rule that sent it.

Why Watcher

  • Nothing is a mystery. The Config Tree shows every value of a host or service and where it comes from: which file, which line, which group. In the web UI and on the command line.
  • Describe your network once. Put hosts into groups by name pattern and give each group its services. A new web server gets its checks the moment it is added, and one service can cover every disk, website or queue on a host.
  • Edit in the browser or in your editor, both at once. The web UI changes the same text files you keep in Git, keeps your comments, and shows exactly what will change before it applies. Edits in your editor are live within a second.
  • Alerts without surprises. Problems are confirmed before anyone is woken up, flapping services are held back, and notification rules don't depend on their order: every matching rule notifies, and nobody gets the same message twice. Open problems come back as reminders and escalate to the next person until someone acknowledges them, and every notification is logged, so you can see who was told and when. When a router dies, dependencies keep the alerts about everything behind it quiet.
  • No agents. Watcher runs checks on remote machines over SSH, copies its scripts there by itself, keeps passwords and keys encrypted, and pins host keys.
  • Your data stays yours. Metrics and history go into PostgreSQL (with TimescaleDB if you like), with plain SQL views for Grafana, BI tools or your own queries.
  • Up in minutes. One binary and a setup wizard in the browser or the terminal. A database is optional to start with.
  • Ready for large networks. Lists are filtered, sorted and paged on the server and update live, so the web UI stays fast with hundreds of thousands of services.

Features

  • Checks: Nagios plugins, your own scripts (Nagios output, key=value or JSON), results pushed over the API, thresholds with units, built-in ping, TCP, HTTP, DNS and TLS certificate checks.
  • Proxmox VE through its API: cluster quorum, nodes, storages, VMs and containers, backups and pending updates. Watcher finds your VMs and containers and adds them as hosts with one click.
  • Remote checks over SSH with encrypted secrets, pinned host keys and automatic script copies.
  • Alerting: SOFT and HARD states with retries, host UP/DOWN, flap detection; email, webhooks, Slack, Microsoft Teams, Telegram, ntfy, Gotify, PagerDuty, Jira and scripts; reminders, escalations, dependencies and time periods (business hours, on-call at night).
  • Operations: acknowledgements, one-off and recurring downtimes, muting and re-checks, from a right-click menu or on many selected hosts and services at once.
  • Web UI: tactical overview, problems, host and service groups, alert history, graphs, configuration forms and a file editor that checks as you type.
  • Data: PostgreSQL or TimescaleDB, SQL views, read-only database logins, copies to a central database.
  • Access: user accounts with admin rights, two-factor authentication (TOTP), HTTPS with certificates from Let's Encrypt.
  • API: everything the web UI does, with tokens for your scripts.

Status

Watcher is in early development. A single instance monitors your network today; see what works today.

Coming next: checks on remote nodes that report to a central hub (nodes can already join a hub and stay connected), repairing data in graphs, and native checks for IBM i, AIX, HMC and MQ.

Getting started

There are no prebuilt releases yet. Build Watcher from source (Rust and Node.js), then start the setup wizard:

git clone https://github.com/mergedeyes/watcher && cd watcher
npm --prefix web ci && npm --prefix web run build
cargo build --release
mkdir ~/watcher && cd ~/watcher
/path/to/watcher/target/release/watcher setup    # open the URL it prints

Installation covers PostgreSQL, HTTPS and running Watcher as a service. First steps takes you from an empty setup to your first monitored host.
